# Подготовка CoffeeRun до Room

Пользователь поручил выполнить подготовку из обсуждения: защита избранного/профиля, быстрые переключения избранного, сохранность изменений корзины при оформлении, правила будущего хранения и итоговая проверка. Room, замена библиотек, коммит/push/PR не разрешены этим шагом.

## Решение

Повторно использовать SessionProvider и перенос контекста в HTTP-запрос. Общую отмену и проверку сессии вынести из заказов в небольшой общий помощник. В избранном хранить подтверждённое состояние и последние ожидающие намерения по ID; чтение накладывает ожидающие значения, старые ошибки не откатывают новые намерения. Запросы сериализуются отдельно для каждого входа и живут в scope приложения. Для профиля защищать загрузку и сохранение, наблюдать смену поколения даже при одинаковом токене; формы снимают busy при отмене.

Пользователь выбрал: при выходе/смене аккаунта очищать корзину и стек навигации; при успехе оформления удалять только отправленное количество, сохраняя добавления. Гостевая корзина при входе для оформления остаётся. Очистка корзины наблюдает сессию в scope приложения; сохранённый владелец навигации переживает пересоздание Activity. Данные для Room описаны в docs/ROOM_PLAN.md; таблицы не создаются.

## Проверки и работа

- [x] RED для позднего избранного после выхода, refresh поверх кликов и старой ошибки переключения.
- [x] Общая защита сессии, избранное, профиль и их вызывающий код/тесты.
- [x] Проверки повторного входа с одинаковым токеном, гостя, поздних результатов/ошибок профиля, отмены сохранения и закрытия экрана во время переключения.
- [x] RED и исправление очистки корзины по согласованному правилу, снимок всех параметров оформления.
- [x] Описать минимальный объём Room и ограничения без реализации БД.
- [x] Все unit-тесты, debug APK, целевые UI-тесты основного пути, независимое read-only ревью, diff check и обновление roadmap.

Ограничения: отмена на клиенте не отменяет уже выполненную операцию сервера. Строгое восстановление исхода заказа и порядок после сетевого тайм-аута требуют сервера (B05). Повтор по текущим ценам/опциям и правила расписания не входят в согласованный список подготовки. Пользовательские комментарии в избранном и изменения Mockoon сохранить.

## Проверки и решения

- RED: три регрессионных теста избранного упали на старом коде; после исправления прошли. Два теста оформления показали потерю новых порций/строк и повторно добавленной строки; после removeOrdered прошли.
- Избранное координирует существующий репозиторий, без отдельного перенаправляющего класса. Сохранён toggle для совместимости UI: внутри команды преобразуются в явное состояние с версией. Актуальная ошибка откатывает последнее намерение и сообщает о сбое; старая ошибка не откатывает новое. Временное расхождение с сервером после неизвестного сетевого исхода остаётся видимым ограничением.
- На Windows обнаружена причина падений старых DataStore-тестов: Android SDK_INT в JVM-заглушке равен 0, ветка File.renameTo не заменяет существующий файл. В тестах используется существующий OkioStorage с PreferencesSerializer; зависимости и Android-хранилище не менялись. Общий прогон после исправления прошёл.
- Независимое read-only ревью выявило две ошибки жизненного цикла: очистка корзины прекращалась при закрытии Activity, а восстановленная навигация теряла связь с предыдущей сессией. Оба случая воспроизведены UI-тестами (RED). Очистка перенесена в scope приложения, владелец навигации сохраняется через rememberSaveable. Все четыре OrderSessionTest прошли (GREEN), включая закрытие Activity и выход во время её пересоздания.
- После исправлений ревью: все 196 unit-тестов прошли, debug APK и APK Android-тестов собраны. Первоначальный NavigationTest: 20/21, выбор самовывоза недоступен в 23:00 GMT. Для повторного UI-прогона только тестовый эмулятор переведён на 10 ноября 2026, 12:00 Europe/Moscow; часы компьютера не менялись. Результаты повторного прогона записываются ниже.
- Коммит, push и PR не выполняются без отдельного разрешения.
- Дополнительная граница восстановления: нулевой счётчик нового процесса мог совпасть с сохранённым владельцем старого стека. `SessionStateStoreTest.restoredOwnerFromAnotherProcess_isNotCurrentSession` воспроизвёл ошибку (RED). Начальная версия теперь получает случайное значение из большого диапазона и увеличивается при смене входа. Это сбрасывает восстановленный защищённый стек после завершения процесса, сохраняя вход по токену; ограничение явно описано в ROOM_PLAN.

## Итог

Финальный запуск `testDebugUnitTest assembleDebug connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=ru.coffeerun.OrderSessionTest`: BUILD SUCCESSFUL, 197 unit-тестов без ошибок и 4 OrderSessionTest без ошибок. Новый тест другого процесса прошёл после исправления (GREEN). Отдельно прошли NavigationTest 21/21, GuestTest 3/3, FavoritesErrorTest 1/1 и OrderHistoryTest 3/3 — всего 32 целевых UI-теста. После последнего изменения начальной версии повторены все unit-тесты и 4 UI-теста с настоящим TokenStore; остальные UI-классы используют неизменённые по этому пункту in-memory фейки.

Оба существенных замечания независимого ревью исправлены и подтверждены RED → GREEN. Проверки whitespace/diff прошли, API и зависимости не менялись. Полный набор всех androidTest-классов не запускался; целевые классы охватывают покупку, гостевой вход, ошибки избранного, историю и жизненный цикл. Не проверялась реальная синхронизация с удалённым сервером: UI-тесты используют управляемые API/фейки. B05, B07 и B09 остаются открытыми; это не обязательная часть согласованной подготовки до Room.
