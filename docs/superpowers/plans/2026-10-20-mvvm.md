# MVVM

## Цель

Разделить код на три слоя с однонаправленным потоком данных:

- **Model** (`ru.coffeerun.data`) — `CartRepository`, `OrderRepository`: данные и правила (слияние строк, лимит `MAX_QUANTITY`, нумерация заказов). Наружу только `StateFlow`, менять — только методами.
- **ViewModel** (`ui/screens/*ViewModel.kt`) — одна на экран, живёт пока экран в back stack. Берёт данные из репозиториев, принимает действия пользователя. Не знает про `NavController` и `Context`.
- **View** — stateless `*Screen` composable. Получают данные и лямбды; навигация — в `CoffeeRunApp`.

```
View ──событие──▶ ViewModel ──▶ Repository
  ▲                                │
  └──── StateFlow ◀────────────────┘
```

## Решения

- **DI вручную**: `AppContainer` в `CoffeeRunApplication`, ViewModel создаются `viewModelFactory { initializer { … } }` через `CreationExtras.container`. Hilt не нужен для двух репозиториев.
- **Аргументы маршрута** читаются в фабрике (`createSavedStateHandle().toRoute<…>()`) и передаются в конструктор ViewModel — так её можно тестировать без Android.
- **Навигация после действия**: `CheckoutViewModel.placeOrder()` возвращает `Order?`, переход делает View. `PlacedRoute(orderNumber)` вместо глобального `lastOrder`.
- **Счётчик корзины** — `List<CartLine>.itemCount`; нижняя панель берёт `CartViewModel` уровня Activity.
- **UI-состояние остаётся в UI**: выбранная категория меню, скролл.
