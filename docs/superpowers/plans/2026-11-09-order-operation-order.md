# Последовательная обработка запросов заказов — B03

Согласовано пользователем: запросы заказов выполняются последовательно в пределах одного входа. Новый вход не ждёт запросов прежнего. Коммит, push и PR требуют отдельного разрешения.

Причина: refresh заменяет список целиком, load/place/cancel изменяют тот же кеш независимо. Защита поколения сессии не упорядочивает ответы одного поколения.

Область: NetworkOrderRepository и его unit-тесты. Интерфейс OrderRepository, ViewModel, API, зависимости и тестовые репозитории менять не требуется. Room не добавляется.

- [x] Ввести отдельный Mutex операций для каждого поколения сессии. Ожидание и запрос входят в отменяемый дочерний scope операции; кеш и выбор Mutex защищены существующим SessionProvider.
- [x] При 409 отмены загрузить актуальный список внутри текущей операции, без повторного захвата Mutex и ожидания общей загрузки, которая сама может ждать эту отмену.
- [x] Сохранить объединение refresh, отмену отдельного ожидающего, очистку при выходе и независимость нового входа.
- [x] Проверить ошибки, отмену ожидающей операции и пересечение 409 с refresh; выполнить все unit-тесты, debug-сборку и компиляцию Android-тестов.
- [x] Проверить diff и обновить roadmap. Коммит не создавать.

Ограничение: медленная загрузка задерживает следующие операции того же входа. Последовательность на клиенте не гарантирует порядок завершения запросов на сервере после тайм-аута; восстановление исхода оформления относится к B05.
