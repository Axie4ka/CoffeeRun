# Подготовка к лабе 5 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подготовить CoffeeRun к лабе 5 («Асинхронность, сеть и репозитории»): CI, каталог как данные с `id`, асинхронный `MenuRepository` за интерфейсом, `UiState` с загрузкой и ошибкой — так, чтобы в лабе 5 оставалось только добавить сетевой источник.

**Architecture:** Слои `model` → `data` → `ui` сохраняются (см. `2026-10-20-mvvm.md`). Каталог перестаёт быть `enum` и живёт в `data/LocalMenu.kt`; экраны получают его через `interface MenuRepository` с `suspend`-методами. ViewModel загружают данные в `viewModelScope` и отдают `StateFlow<XxxUiState>`; экраны рисуют Loading / Error / Success. В лабе 5 рядом с `LocalMenuRepository` появится `NetworkMenuRepository`, и меняется одна строка в `AppContainer`.

**Tech Stack:** Kotlin 2.2.10, Jetpack Compose (BOM 2026.02.01), Navigation Compose 2.10.2 (типобезопасные маршруты), Lifecycle 2.11.0, kotlinx-coroutines-test, JUnit 4, GitHub Actions.

**Spec:** решения из обсуждения 2026-10-20 (раздел «Пересобранный план по лабам» — «Сейчас, до лабы 5») и `docs/superpowers/plans/2026-10-20-mvvm.md`.

## Global Constraints

- Ресурсы (`@StringRes`, `@DrawableRes`) в `Product` **остаются** в этом плане — их замена на `String`/`imageUrl` относится к лабе 5. Здесь меняется только «enum → data class с `id`».
- Новые строки — в `app/src/main/res/values/strings.xml` (английский, по умолчанию) **и** `values-ru/strings.xml`.
- ViewModel не знает про `NavController` и `Context`; навигация — в `ui/CoffeeRunApp.kt`.
- Зависимости только из `gradle/libs.versions.toml`; новая — только `kotlinx-coroutines-test` (`1.10.2`, `testImplementation`).
- Локальный запуск Gradle из терминала агента: `GRADLE_USER_HOME=C:\Gradle`, `JAVA_HOME` = JBR Android Studio, `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=<ascii-путь>` (кириллица в путях профиля).
- Каждая задача заканчивается зелёными `testDebugUnitTest` и `connectedDebugAndroidTest` (эмулятор) и отдельным коммитом.

## Review Focus

1. **«Повторить» после ошибки** — Error → Loading → Success, а не залипание в Error. Тест: `MenuViewModelTest.retry_afterError_loadsMenu` (Task 3).
2. **Поворот экрана во время загрузки** — загрузка не запускается второй раз. Тест: `MenuViewModelTest.menu_loadsOnce` — счётчик вызовов фейкового репозитория = 1 после двух подписок (Task 3).
3. **Неизвестный `productId`** (восстановленный стек после смены каталога) — экран позиции не падает, а возвращает в меню. Тест: `ProductViewModelTest.unknownId_isNotFound` (Task 4).
4. **Форма переживает пересоздание и при асинхронной загрузке товара** — выбранный размер не сбрасывается после загрузки. Тест: `ProductViewModelTest.form_survivesWhileProductLoads` (Task 4).
5. **Строки корзины с одинаковым товаром сливаются** после перехода с `enum` на `data class` (равенство по полям). Покрыто существующими `CartTest.quickAdd_hasSizeAndMergesWithSameDrinkFromProductScreen` и `ProductViewModelTest.addToCart_buildsLineThatMergesWithQuickAdd` — должны остаться зелёными в Task 2.
