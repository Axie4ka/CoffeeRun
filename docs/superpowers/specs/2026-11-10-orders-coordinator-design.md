# Выделение OrdersCoordinator

Пользователь согласовал следующий этап после избранного: coordinator заказов, явная загрузка вместо конструктора, общий список и защита устаревших ответов. Выполняем в текущей feature-ветке без commit/push.

## Границы

- `Orders` — контракт для UI: общий список, признак полной загрузки, наблюдение одного заказа, refresh/place/cancel/load/find.
- `OrderRepository` — подтверждённые данные и сетевые операции с явно указанной AuthSession. Никаких scope, Mutex, Deferred и автозагрузки.
- `OrdersCoordinator` — единственный путь сетевых операций UI: один Mutex операций на поколение сессии, общий запрос параллельных refresh, очистка при смене входа. Наблюдатель сессии только очищает состояние, сеть не запускает.
- Ошибка 409 отмены переводится репозиторием в TooLate; coordinator обновляет список внутри текущей блокировки, без повторного захвата.
- Репозиторий по-прежнему атомарно проверяет сессию и изменяет кеш. UI наблюдает те же данные через Orders; новый Store не вводится.
- Экран списка и детали явно запрашивают данные. Профиль запрашивает полный список, если его ещё нет; до загрузки число неизвестно, а не 0. Retry профиля повторяет неудавшуюся загрузку.
- Зависимость истории от меню, восстановление принятого заказа после процесса, PickupPolicy и use cases оформления/повтора остаются следующими задачами.

## Решения

Сохраняем последовательное выполнение вместо сложного слияния версий ответов. Общий refresh остаётся нужен для одновременного запроса профиля/вкладки и для сохранения поведения отмены одного ожидающего. Его короткое состояние согласуется существующим SessionProvider.withSession, второй Mutex loading больше не нужен. Контракты пока остаются на существующих путях data, как в первом этапе; общий переезд пакетов отдельный.

## Проверки

Перенести конкурентные тесты на coordinator с настоящим сетевым репозиторием, заменив автоматическую начальную загрузку явной. Отдельно проверить конструктор без GET, явную загрузку нового входа, общий refresh и отмену ожидающего, 409 без deadlock, устаревшие ответы включая 404 и одинаковый токен. Проверить профиль: неизвестный/нулевой/непустой счётчик, ошибка и retry, гость. Полная unit-сюита, APK и UI-тесты.
