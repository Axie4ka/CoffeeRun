# Order session protection Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for this approved step. No commits, push or PR without explicit user approval.

**Goal:** Ответы запросов заказов предыдущей сессии не восстанавливают и не изменяют данные после выхода или нового входа.

**Architecture:** Общий SessionProvider предоставляет версию сессии, поток смен и атомарную проверку при применении результата. TokenStore сохраняет токен в DataStore, а согласованный снимок токена и версии хранит в памяти; версия меняется при каждом успешном сохранении токена, включая одинаковую строку. NetworkOrderRepository привязывает операции к версии, отменяет ожидающие операции при смене сессии и применяет результат под той же защитой, что и смена версии.

**Tech Stack:** Существующие Kotlin/coroutines/Flow/DataStore/Retrofit/JUnit. Room добавляется в ЛР6, новых зависимостей нет.

**Spec:** Согласованный третий шаг из чата и B01 в `docs/ROADMAP.md`. Уточнено пользователем: в ЛР6 пока известно только требование локальной БД, перенос токена в Room не требуется.

## Constraints

- Подключить общий механизм только к сетевым заказам; избранное и профиль переводятся отдельно.
- Токен и пароль не включать в публичный AuthSession; пароль не сохраняется.
- Сохранить чтение токена после перезапуска и защиту нового входа от старого 401, в том числе при одинаковой строке токена.
- Проверка версии и изменение кеша выполняются атомарно, сетевое ожидание не удерживает блокировку.
- Отмена клиента не обещает отмену уже выполненной сервером операции.
- Согласованность разных запросов внутри одной сессии (B03), идемпотентность оформления (B05) и Room не реализуются в этом шаге.
- Существующие пользовательские изменения и предыдущие два шага сохранить; новую ветку не создавать.

- Пользователь уточнил требования ЛР6; токен остаётся в DataStore, версия текущих запросов — в памяти.
- Регрессионные сценарии сначала воспроизвели ошибки, затем прошли после исправлений. Дополнительно проверены новый вход без промежуточного выхода, отмена одного потребителя общей загрузки и запрет персонального запроса гостя.
- Независимое ревью выявило два случая. После записи DataStore отмена могла прервать публикацию состояния в памяти: запись и публикация теперь завершаются вместе в коротком NonCancellable-блоке. Старый запрос в очереди OkHttp мог получить токен нового входа: версия передаётся через контекст корутины в тег запроса, AuthInterceptor проверяет её до отправки. Для обоих случаев получены RED → GREEN; отдельный тест проверяет передачу версии через настоящий Retrofit.
