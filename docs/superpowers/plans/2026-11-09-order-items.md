# OrderItem Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for this approved step. Track progress below. Do not commit without the user's explicit approval.

**Goal:** Отделить строки оформленного заказа от корзины и сохранять в истории товары, отсутствующие в меню.

**Architecture:** `Order.lines` содержит `OrderItem` со стабильным ID товара, необязательным названием/описанием, оплаченной ценой, количеством и выбранными опциями. Модель не хранит `Product`. Отсутствующее название заменяется локализованным текстом только в UI. Пока сервер не возвращает исторические тексты, доступные названия берутся из каталога.

**Tech Stack:** Kotlin, Compose, существующие Retrofit/Flow/JUnit. Room добавляется в ЛР6.

**Spec:** Согласованный в чате первый вариант; контекст — `docs/ROADMAP.md`, B08/A05.

## Global Constraints

- Изменяется только согласованный шаг. API и `mock/coffeerun.json` сохраняются.
- Существующие пользовательские изменения не редактируются.
- Новые зависимости и Room в этом шаге не добавляются.
- При неизвестном названии показывать «Товар недоступен» / «Item unavailable».
- Пользователь выбрал частичный повтор: добавлять доступные товары и сообщать о пропущенных. Если доступных нет, оставаться на экране заказа. Перерасчёт актуальных цен и опций относится к следующему сценарию.
- Коммит, push и PR требуют отдельного согласования.

## Review Focus

- Отсутствующий товар не теряет количество, опции, цену и стоимость строки.
- Одинаковый productId в нескольких конфигурациях сохраняется отдельными строками.
- Отмена заказа сохраняет уже известные тексты строк без создания фиктивного Product.
- UI не содержит жёстко заданного русского названия неизвестного товара.
- Повтор не создаёт доступный товар из неизвестной позиции истории.
